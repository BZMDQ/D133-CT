# 实施说明

## 分区与启动

板卡资料和原 SDK 确认 NOR 为 16 MiB。使用连续分区，64 KiB 对齐；所有起点与大小均为擦除块整数倍。

| 区域 | 偏移 | 大小 | 用途 |
| --- | ---: | ---: | --- |
| SPL / Factory Bootloader | 0x000000 | 512 KiB | 首次 USB 工厂部署；日常 OTA 不写 |
| ENV | 0x080000 | 128 KiB | 官方环境变量主区 |
| ENV_R | 0x0A0000 | 128 KiB | 官方冗余环境区 |
| OS_A | 0x0C0000 | 2 MiB | RT-Thread 系统槽 A |
| OS_B | 0x2C0000 | 2 MiB | RT-Thread 系统槽 B |
| RODATA_A | 0x4C0000 | 5 MiB | 只读 FATFS 资源槽 A |
| RODATA_B | 0x9C0000 | 5 MiB | 只读 FATFS 资源槽 B |
| DATA | 0xEC0000 | 1 MiB | 单个 LittleFS 可写分区 |

占用 15.75 MiB，末尾保留 256 KiB。最终构建以 `partition.json` 和 `partition_file_list.h` 为准。相同 OS/RODATA 工厂镜像写入双槽。编译得到的 OS ITB 与 RODATA 镜像大小必须分别小于 2 MiB 和 5 MiB；超出时 image pack 会失败。

## NOR 读取和开机显示

启动介质是板载 16 MiB SPI NOR。当前 SDK 的 D133CBS 配置默认将 QSPI0 NOR 总线频率和控制器源频率设为 100 MHz，数据总线为四线，接收采样延迟为半周期（模式 2）；本工程已将这些值显式写入首次部署 Bootloader、工厂 OS 和 OTA OS defconfig。CPU/总线保持 SDK 板级目标的 CPU 480 MHz、AXI/AHB 200 MHz、APB 100 MHz。100 MHz 是目前有 SDK 默认配置依据的 NOR 读速基准，不代表已在这块板上测出的最大稳定频率。由于本地资料未确认 SPI NOR 精确料号，超过 100 MHz 前需先核实芯片手册，并在目标板进行冷启动、温度和电压边界测试；本次没有盲目超频。

## 启动速度优化与实测边界

本次配套 Bootloader 关闭预启动 Logo/黑屏写入，避免在 OS 接手前重复初始化面板；OS 保留 LVDS 黑屏初始化以提前预热面板。工厂和 OTA defconfig 将 ULOG 静态输出级别从 Info 调到 Warning，并关闭当前 HMI 未调用的 CAN0、音频、TSEN/GPAI 驱动；SD、RMII、I²C 触摸、RTC、看门狗和 LVDS 保留。HMI 共用一个 18 px FreeType 字体实例，减少启动时字体对象创建。CPU 480 MHz、总线时钟与 QSPI 100 MHz 四线配置没有改高，A/B 健康确认、看门狗、OTA 验签和失败回滚保持启用。

启动日志增加 `[boot_time]` 阶段标记：`app_services_ready`、`hmi_ui_enter`、`chinese_font_ready`、`hmi_widgets_ready`、`lvgl_render_ready` 和 `display_flush_return`。这些时间从 RT-Thread app 初始化开始计，不包含 BootROM、SPL、Bootloader，也不能完全代表屏幕实际发光；完整 1 秒验收需要用目标板从上电沿测到可触控首页。当前只有固件编译证据，没有板上冷启动数据，不能承诺已经达到 1 秒。测量方法见 [启动优化与实测](启动优化与实测.md)。

已定位 v1.0.0 仍显示色块的原因：SDK 的 `AIC_DISP_BOOTUP_LOGO` 默认选择 `AIC_DISP_COLOR_BLOCK`，显示驱动会按 100 像素方块绘制蓝/绿/红/黑/白测试图。当前配套 Bootloader 关闭预启动 Logo；工厂 OS 和 OTA OS 保留 `AIC_DISP_BLACK_SCREEN=y` 并关闭 `AIC_DISP_COLOR_BLOCK`，OS 初始化 LVDS 时清黑屏，官方 LVGL 线程启动后直接创建中文 HMI 首页。同时关闭 `AIC_STARTUP_UI_SHOW` 和 `AIC_LVGL_DEMO`。中文字体由 FreeType 从 `/rodata/hmi/fonts/NotoSansSC-HMI.ttf` 加载，约 2.43 MiB，随 A/B RODATA 更新。工厂构建的 RODATA 镜像约 2.50 MiB，小于 5 MiB 槽位。实际冷启动耗时和 NOR 读稳定性仍需在板上测量；本地构建不会测出实机毫秒数。

官方 Bootloader 的 ENV 逻辑在升级期间试启动。HMI 策略将失败槽回退扩展为 OS/RODATA 成对回退；DATA 始终保持原槽。Bootloader 在候选系统前启动 60 秒看门狗并递增 `bootcount`。RT-Thread GUI 启动后改用 15 秒看门狗，要求 LVGL 心跳、GT911 设备、`/rodata` 与 `/data` 均正常，连续 30 秒后才调用官方 `aic_ota_status_update()` 清除升级标志。

## 第一阶段交付和烧录

首次部署、更新配套 Bootloader 或获得本次启动优化和顶栏调整，请使用 `downloads/d13x_d133cbv-hmi-nor_v1.0.16.img`，它包括配套 SPL/Bootloader、ENV、双 OS、双 RODATA 与 DATA，保留官方 USB BROM/AiBurn 与 SD/USB 恢复组件。已签名 OTA v1.0.9 低于工厂 v1.0.16。量产或维护时按板卡说明在 PA0 UBOOT 键上电进入 USB 烧录模式，再选择对应 D133CBS 工厂镜像。工厂镜像编译和复制完成不代表已烧进开发板；需要你手动用 AiBurn 烧录。本工程没有执行烧录、擦除或分区写入。

最终生成文件：SDK 输出 `output/d13x_d133cbv-hmi-nor_rt-thread_d133_hmi/images/`。本工程 `downloads/` 保存交付副本。烧录后的触摸、显示、SD 插拔、RMII PHY 和自动回滚仍需目标板验证。

## SD/FATFS 与文件页

板级 pinmux 复用 SDK 的 SDMC1 PC0–PC6；PC6 是插卡检测。官方 `drv_sdcard.c` 热插拔线程处理插拔，board mount table 将 FATFS 自动挂载为 `/sdcard`。`sd_manager` 查询该挂载，`storage_manager` 使用 RT-Thread 消息队列把 POSIX DFS/FATFS 文件操作送到独立线程。列表每页最多显示 32 项，长列表可刷新；纯文本读取/写入上限 511 字节。创建文件夹、复制、改名、删除、浏览、大小和容量查询均在工作线程执行。选中 JPG/JPEG、PNG 或 16/24/32 位 BMP 后按“打开 / 读取”会进入全屏裁切铺满页，左上角有触摸返回键。文件读取和解码由独立图片线程完成，LVGL 线程只创建/更新控件。JPEG 由 MPP 缩放到不超过 1024×600；PNG/BMP 支持不超过 1024×768；单文件上限 4 MiB。各解码格式在原 MPP 缓冲区内归一为屏幕 RGB565，不额外申请大块 CMA；透明 PNG 按预览底色合成。UART0 `[image_preview]` 日志用于解码故障定位。删除、写入和 OTA 提交有界面确认。`/sdcard/UPDATE` 由 OTA 服务保留。

SD OTA 文件放在 `/sdcard/UPDATE/ota.cpio`，并带同名 `/sdcard/UPDATE/ota.cpio.sig`。先用 `scripts/sign_ota.ps1` 对 OTA CPIO 签名；签名采用 RSA-2048/SHA-256，公钥随只读资源部署在 `/rodata/hmi/ota_public.pem`。缺少签名、公钥、SHA256 或槽位容量校验失败时不会调用 OTA 写入。文件页触发 OTA 后，在 LVDS 屏幕确认；成功写入非活动槽并提交官方 ENV 后，设备自动重启。

Luban-Lite 的 `mkcpio.py` 在生成 CRC CPIO 后会回填 `ota_info.bin` 的包长，但没有同步 ENV 内层 CRC 和 CPIO 外层加和字段。本工程 `scripts/prepare_ota.py` 只修复这两个校验字段，并严格验证官方包的成员名、长度、版本及目标分区。它不改变 CPIO 文件映射或写 Flash 逻辑。其输入来自官方 `ota-subimgs.cfg` 的 OS 与 RODATA 输出。

## TCP 与工具箱

开发板作为 TCP 服务端监听 8899。研发工具箱固件升级页选择 `D133CBS · ArtInChip`，设备列表填开发板 IP，选择 `ota.cpio` 和旁边的 `.sig` 文件。工具箱显示逐台收包进度；接收完成后，开发板屏幕要求确认。状态成功只在重新连接后核对运行版本、启动槽和 `upgrade_available=0` 健康确认时报告。

协议使用现有 Local TCP `LNET` 20 字节帧结构和 CRC32，命令 0xD100–0xD104 分别为信息、开始、数据分片、提交、RSA 签名。开始信息包括长度、SHA256、产品、硬件和版本；每片最大 16 KiB，设备应答下一偏移。工具箱源代码副本位于 `toolbox/Source/`，版本 0.8.34。工具箱原 STM32F750 `.ota.bin` 入口保持原格式；D133 入口独立检查 ArtInChip CPIO。

`keys/development_private.pem` 是本工程生成的开发签名私钥，只用于本地开发包，不能用于量产。量产必须替换受控 RSA 私钥/固件内公钥，启用适合工厂密钥保管和防回滚的流程。第一版 TCP 为明文 LAN 传输，RSA 签名提供固件真实性、SHA256 提供包完整性，开发板屏幕提供人工授权；它们不提供链路保密性。量产还须用受信任 CA/证书固定或 TLS 设备身份认证保护 TCP 控制面。

## LVGL 页面

六页共用白色主背景、浅蓝应用卡片、顶部品牌/状态栏、青色分隔条、蓝色操作按钮与 Noto Sans SC 中文字体，延续用户提供的 STM32F750 v1.4.7 应用启动器样式。首页采用 5×3 网格，仅显示六个已实现应用卡片；设备总览详情在独立页面打开，子页面通过顶部返回键回到启动器；7 英寸屏幕触控按钮高 48 像素：

1. 首页：产品/硬件、IP/链路、SD 状态、当前与下次 OS 槽、RODATA 槽、健康状态和运行时间。
2. 文件管理：目录列表、返回/进入目录、文本读取预览、SD 卡 JPG/JPEG/PNG/BMP 全屏图片预览（左上角返回）、文本保存、复制、重命名、删除、新建文件夹、容量查询。
3. 固件升级：SD 包安装、版本和进度、错误提示、重新启动；远程 TCP 请求需要触屏确认。
4. 系统信息：版本、芯片与硬件、OS、LVGL、屏幕和存储配置。
5. 网络设置：RMII 链路/IP 查询、运行时 DHCP 或静态 IPv4 设置、TCP 端口。重启后恢复 defconfig 中的默认地址。
6. 系统日志：运行状态和 DATA LittleFS 的滚动日志。`/data/upgrade.state` 记录预备、提交、确认或回退状态。

LVGL 对象只由 `lv_user_gui_init` 所在的官方 LVGL 线程创建和更新。文件、图片解码、TCP 和 OTA 工作线程不创建或修改控件；图片线程通过状态和只读像素描述符交接结果，页面定时器在 LVGL 线程创建预览控件。

## v1.0.17 OTA 包与发布资源

工厂 defconfig 当前为 HMI `1.0.16`，OTA 候选 defconfig 为 `1.0.17`。候选 defconfig 自标识指向自身，避免 Luban-Lite 退回工厂 profile。执行 `scripts/build.ps1 -Target OtaCandidate` 时，构建脚本把候选版本同步到 OS 宏和构建用 image_cfg，输出的 OS、CPIO、OTA 元数据三者版本相同。候选构建目录为 `output/d13x_d133cbv-hmi-nor_rt-thread_d133_hmi_ota/images/`。v1.0.17 已由该 SDK 构建生成；`prepare_ota.py` 修复并校验官方 CPIO 字段后生成版本化下载包，再用本地开发私钥签名。

```powershell
& ..\..\D133CES\luban-lite-master\tools\env\tools\Python38\python3.exe scripts/prepare_ota.py ..\..\D133CES\luban-lite-master\output\d13x_d133cbv-hmi-nor_rt-thread_d133_hmi_ota\images\ota.cpio downloads/d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio --version 1.0.17
pwsh -File scripts/sign_ota.ps1 -Package downloads/d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio -PrivateKey keys/development_private.pem
& ..\..\D133CES\luban-lite-master\tools\env\tools\Python38\python3.exe scripts/verify_ota_host.py downloads/d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio
pwsh -File scripts/verify_ota_signature.ps1 -Package downloads/d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio -Signature downloads/d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio.sig -PublicKey source/application/rt-thread/d133_hmi/assets/ota_public.pem
```

发布资源：`d13x_d133cbv-hmi-nor_ota_v1.0.17.cpio`（3,904,512 字节，SHA-256 `1afeacc25a3db43bdc4885697662d3ceec0bbe1acc753bf8d648e836a5b3c51b`）、同名 `.sig`（256 字节）、`.json` 元数据、`.sha256` 校验文件，以及首次部署用 `d13x_d133cbv-hmi-nor_v1.0.16.img` 和 `SHA256SUMS_current.txt`。包已通过 `verify_ota_host.py` 的 CPIO 成员、分区白名单、CRC、版本、篡改和尾随数据检查，并通过 RSA-2048/SHA-256 验签。包和开发签名文件会作为 GitHub Release 附件发布，不写入 Git 历史；开发密钥不发布。将 SD OTA 文件放入 `/sdcard/UPDATE/` 时，须按板端约定命名为 `ota.cpio` 与 `ota.cpio.sig`。首次部署仍使用 v1.0.16 工厂镜像；v1.0.17 OTA 尚未进行目标板升级与回滚实测，发布说明会标为预发布。
