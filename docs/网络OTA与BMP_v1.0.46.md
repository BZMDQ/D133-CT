# v1.0.46 网络 OTA 和 BMP 调度改进

原 TCP 服务在 COMMIT 连接内等待 OTA 校验、用户确认和写入，最长 180 秒；这期间没有再次 accept，工具箱的新健康查询连接无法被处理。

此版使用两个连接工作线程、独立报文缓冲及单一上传互斥锁。升级连接等待结果时，另一连接仍可查询 OP_HEALTH/OP_INFO。JSON 保留原字段并新增 ota_state、ota_percent、ota_error；LNET 操作码、最终提交响应及签名要求保持兼容。状态编号：0 空闲、1 等待屏幕确认、2 校验、3 写入、4 待重启、5 失败。

上传、官方校验和写入仍有各自耗时，本次修复不能证明所有硬件卡死均已排除。远程升级仍需屏幕确认；约 60 秒未确认会失败。写入每 64 KiB 让出一次 CPU，以便网络查询与界面运行。两个连接工作线程各有 24 KiB 栈。

BMP 转换线程时间片由 10 tick 改为 2 tick，与预读线程一致，减少相同优先级下预读等待转换线程让出 CPU 的时间。保留 512 KiB 每块的双缓冲和低内存回退；不会保证所有图片提速。

## 手动验证

1. 备份配置和数据后，使用 AiBurn 手动烧录 v1.0.46 工厂 IMG。工厂包包含配套 Bootloader，可能覆盖 ENV 和 DATA；没有执行自动烧录。
2. 通过工具箱上传更高版本的有效签名 OTA 包。传输结束后在屏幕确认，观察校验、写入、重启与槽位确认。
3. 升级连接等待期间，另开健康查询连接，应能返回上述状态；等待确认应显示状态 1，签名错误应失败且不提交启动槽位。
4. 测试断线重试、无效包、重复 BEGIN、升级时再次尝试上传、写入期间 UI 响应。并发上传应被拒绝，不允许同时写暂存文件。
5. 用同一 SD 卡和同一 BMP 对比 v1.0.45/v1.0.46 打开耗时、颜色、取消及返回后重开。

以上均为待上板验证项目。主机编译成功不代表完成设备 OTA 或性能验收。
