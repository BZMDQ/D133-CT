# 启动优化与实测

## 本次优化

- 配套 Bootloader 不再初始化预启动黑屏 Logo，避免正常启动时先点亮 LVDS、OS 接管后再初始化一次。LVDS 驱动仍保留，OS 继续清黑屏并显示 HMI。
- RT-Thread ULOG 从 Info 调到 Warning，启动期仍保留警告和错误日志。
- 工厂和 OTA profile 关闭当前 HMI 未使用的 CAN0、音频、TSEN/GPAI 驱动，保留 SD、RMII、I²C 触摸、RTC、看门狗及 LVDS。
- HMI 的 16/18 px 控件共用一个 FreeType 字体实例，减少重复字体对象创建。
- 图片预览线程改为首次打开 SD 图片时才创建，首页启动不再初始化该后台服务。
- 应用卡片把图标底板和符号合并为单个 LVGL Label，减少首页控件数量。
- 首页隐藏状态胶囊和设备总览摘要；顶栏增高至 90 px，Logo 与青色分隔线之间保留间距。
- UART0 增加 `[boot_time]` 标记：`app_services_ready`、`hmi_ui_enter`、`chinese_font_ready`、`hmi_widgets_ready`、`lvgl_render_ready` 和 `display_flush_return`。
- CPU 480 MHz、AXI/AHB 200 MHz、APB 100 MHz、QSPI NOR 100 MHz 四线配置保持不变；没有超频，也没有绕过 A/B 健康确认、看门狗或 OTA 验签。

## 计时范围

`[boot_time]` 数值从 RT-Thread 的 `app_manager_init()` 开始计时，能比较应用服务、字体、HMI 控件和 LVGL 首帧路径。本标记不包括 BootROM、SPL、Bootloader，也不能严格代表 LCD 已完成一整帧扫描。

因此，目前只能确认本地 Bootloader、工厂 OS 和 OTA OS 已编译，**尚无证据证明整机从上电到可触控首页在 1 秒内完成**。需要在目标板上测量完整冷启动；不能根据 SDK 频率配置或编译时间推断启动耗时。

## 用户提供的 v1.0.10 实机日志基线

串口日志报告 `Startup time: 1.627 sec`。同一份记录显示 QSPI 输入时钟为 99 MHz，SPL 读取 1,424,556 字节耗时 29,567 μs，打印读取速度 47,050 KB/s。`display_flush_return=436 ms` 和 `lvgl_render_ready=439 ms` 是从 RT-Thread `app_manager_init()` 开始计算的阶段时间，不能与 `Startup time` 简单相加。v1.0.16 延迟到首次打开图片时才创建预览线程，精简首页控件、隐藏首页状态胶囊并扩大顶栏；目前还没有新版本的板上计时记录，实际收益需重新测量。

## 板上验收方法

1. 为验证 Bootloader 优化及 STM32 风格 5×3 应用启动器，先手动用 AiBurn 烧录 `downloads/d13x_d133cbv-hmi-nor_v1.0.16.img`。已签名 OTA v1.0.9 低于此版本。
2. UART0 从上电开始保存完整日志，记录 `[boot_time]` 六个阶段标记。
3. 用示波器/逻辑分析仪从电源上升沿测到 LVDS 首帧；再触摸首页按钮确认输入已响应。连续冷启动至少 10 次，记录最慢值和中位数。
4. 若 `chinese_font_ready` 明显偏慢，可继续优化字体资产；若 `app_services_ready` 偏慢，按日志定位存储、ENV 或网络初始化。不要移除 A/B 健康确认或 OTA 验签来换取启动时间。
