# 屏幕代号串口协议

## 接口

- UART：UART0，115200 baud，8 data bits，no parity，1 stop bit（8N1）。
- 命令：5 个 ASCII 字符，例如 `CS000`；可直接发送，也可追加 CR、LF 或 CRLF。
- 应答：ASCII 文本，以 CRLF 结束；没有额外控制台日志、校验和或二进制帧头。
- 命令接收由 RT-Thread 工作线程处理，不占用 LVGL 线程。

板端 UART0 为 3.3 V TTL。连接 USB-UART 时交叉连接 TX/RX 并接共地，不要连接 RS-232 电平。D133CBS 板卡 UART0 TX 使用 PA0，PA0 同时连接 UBOOT 按键启动采样；避免在上电时把该线拉低。

## 命令与应答

| 命令 | 应答 | 含义 |
| --- | --- | --- |
| `CS000` | `CS000,OK,ACTIVE=CS000,RES=1024x600,TOUCH=GT911` | 确认当前配置为 CS000；本命令不重启显示链路。 |
| `CS001` | `CS001,ERR,NOT_CONFIGURED,ACTIVE=CS000` | CS001 配置和驱动尚未就绪，拒绝切换并报告当前配置。 |
| 其他代号 | `<代号>,ERR,UNSUPPORTED_CODE,ACTIVE=CS000` | 当前固件未登记该代号。 |

示例：

```text
电脑发送：CS000\r\n
开发板：  CS000,OK,ACTIVE=CS000,RES=1024x600,TOUCH=GT911\r\n

电脑发送：CS001
开发板：  CS001,ERR,NOT_CONFIGURED,ACTIVE=CS000\r\n
```

`CS000` 是当前固化的板级配置：1024×600 LVDS、GT911 触摸。v1.0.22 的正式配置启用 UART0 驱动，但 RT 控制台仍绑定静默设备；命令应答是 UART0 上唯一的 HMI 文本协议输出。这里的编译结果尚未在开发板上验证。

## CS001 新资料核对

新资料的封面把产品规格号列为 `EK79202DA`、客户料号 `ICEK7920321XXXXXXX01`；正文是 EK79202D 2052 通道 source driver/TCON 芯片的 preliminary datasheet。它补充了 1280×800 LVDS 输入的候选时序，但不是完整的 LCD 模组接线规格。

芯片 datasheet 的 1280×800、60 Hz HV mode 表给出：像素时钟典型值 72.4 MHz（范围 66.3–78.9 MHz）、每行 1440 DCLK（显示区 1280）、含同步脉冲的 HBP 88 DCLK、HFP 72 DCLK、HSYNC 脉宽 2–40 DCLK；每帧 838 行（显示区 800）、含同步脉冲的 VBP 23 行、VFP 15 行、VSYNC 脉宽 2–20 行。由典型时钟和总尺寸计算约为 60 Hz。这些是芯片允许的输入 timing，脉宽典型值和模组实际配置未由资料确定。

同一芯片资料说明支持 LVDS 6/8-bit，且以 `IFSEL[1:0]`、`LNSW[1:0]`、`PNSW`、`RES[2:0]`、`LVFMT`、`LVBIT` 等 pin strap 选择接口、lane/polarity mapping、分辨率与数据格式；它列出 1280×800 的 RES 编码，但没有给出该客户模组的实际 strap 电阻/连接器到 D133 LVDS lane 对应表。D133 当前 `panel_simple.c` 只在 `aicfb_probe()` 时静态选择 panel，LVGL 初始化时读取一次 framebuffer 尺寸；SDK 没有现成的运行时屏幕/触摸切换接口。

触摸方面，先前的 LCJ0010R1EA0Y16CP100 样件确认资料提到 ATMXT1066TD、I²C/3.3 V 和 1280×800 触摸分辨率；新 EK79202D PDF 没有 ATMXT1066TD 寄存器/对象表或 CTP 接线资料。当前 SDK 的 `bsp/peripheral/touch/Kconfig` 有 GT911 等选择项，没有 ATMXT1066TD 项，也没有对应驱动源码。

要把 CS001 做成真正可用的显示与触摸配置，还需要：

1. `ICEK7920321XXXXXXX01` 完整模组接口/排线图，特别是 LVDS 单/双链路、D0–D3/clock lane 对应、极性、VESA/JEIDA、HV/DE 模式，以及上电、复位和背光时序/引脚。
2. EK79202DA 模组实际的 `IFSEL/LNSW/PNSW/RES/LVFMT/LVBIT` strap 设置或供应商已验证的接口配置，确认采用上述 1280×800 时序。
3. ATMXT1066TD 的 RT-Thread 驱动/初始化配置，或控制器完整协议、I²C 地址、板端 I²C/IRQ/RESET 接线、报告格式和坐标方向。

因此当前代码仍将 `CS001` 安全地返回 `NOT_CONFIGURED`，不会只凭通用芯片 timing 就切换。拿到模组与触摸资料后，需要添加项目级 CS001 panel profile 和触摸驱动，并把 profile 选择接入显示驱动初始化流程；再编译和检查失败回退。不要直接改写 Flash 地址。

## 串口无应答排查

串口助手设为 UART0 115200/8N1、ASCII 发送 `CS001` 是正确格式。v1.0.22 工厂 IMG 中包含 UART0 协议服务，但该 IMG 只在 SDK 构建并发布，本工程没有代用户烧录开发板；v1.0.21 正式固件关闭了 UART0 驱动，因此运行旧固件时发命令不会收到应答。先在系统信息确认固件版本：v1.0.22 应对 `CS000` 和 `CS001` 都返回一行；若已确认运行 v1.0.22 仍无应答，再检查 UART0 的 TX/RX 交叉、共地和板端接线。

## 验收步骤

1. 使用 3.3 V USB-UART 连接 UART0，设为 115200/8N1。
2. 发送 `CS000`，期望返回 `OK`、`ACTIVE=CS000`、`1024x600` 和 `GT911`。
3. 发送 `CS001`，期望返回 `NOT_CONFIGURED`，当前值仍为 `CS000`。
4. 发送其他 5 字节代号，期望返回 `UNSUPPORTED_CODE`。

以上是协议预期结果。实际串口收发、屏幕切换和触摸仍需在目标板验证；目前 CS001 应当保持拒绝状态。
