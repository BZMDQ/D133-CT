# 屏幕代号串口协议

## UART 接口

- UART0：115200 baud、8 data bits、no parity、1 stop bit（8N1）。
- 命令：5 个 ASCII 字符，例如 CS000；可直接发送，也可追加 CR、LF 或 CRLF。
- 应答：ASCII 文本，以 CRLF 结束。
- RT-Thread/HMI/Shell 控制台保持静默；UART0 只用于屏幕 profile 状态行和命令应答。
- 命令由 RT-Thread 接收线程处理，不占用 LVGL 线程。
- 开机后主动发送当前 profile 行，确认固件和链路已就绪。

板端 UART0 为 3.3 V TTL。USB-UART 需要 TX/RX 交叉并共地，不要接 RS-232 电平。UART0 TX/RX 使用 PA0/PA1；PA0 同时与 UBOOT 按键采样有关，上电时不要把 PA0 拉低。

## 命令和应答

| 命令 | 应答 | 屏幕配置 |
| --- | --- | --- |
| CS000 | 已是当前配置：CS000,OK,ACTIVE=CS000,RES=1024x600,TOUCH=GT911；从 CS001 切换：CS000,OK,REBOOTING,RES=1024x600,TOUCH=GT911 | 1024×600 LVDS，GT911 触摸 |
| CS001 | 已是当前配置：CS001,OK,ACTIVE=CS001,RES=1280x800,TOUCH=DISABLED；从 CS000 切换：CS001,OK,REBOOTING,RES=1280x800,TOUCH=DISABLED | EK79202DA 1280×800 MIPI-DSI 显示；触摸暂时关闭 |
| 其他代号 | <代号>,ERR,UNSUPPORTED_CODE,ACTIVE=<当前代号> | 固件尚未配置该屏幕代号 |

每次启动发送一行：

    CS000,READY,RES=1024x600,TOUCH=GT911
    CS001,READY,RES=1280x800,TOUCH=DISABLED

命令示例：

    电脑发送：CS001
    开发板：  CS001,OK,REBOOTING,RES=1280x800,TOUCH=DISABLED
    设备重启后：CS001,READY,RES=1280x800,TOUCH=DISABLED

profile 修改通过官方 fw_env_write/fw_env_flush 保存到冗余 ENV，随后软件重启。显示控制器和 LVGL display 在启动时创建，因此切换需要重启，不支持运行中热切换。若启动时 ENV 不可读，安全默认值为 CS000/LVDS。

## CS001 MIPI 配置来源

CS001 对应资料 ICEK7920321XXXXXXX01，PDF 正文为 EK79202D source driver/TCON 芯片 preliminary datasheet。资料确认该芯片支持 MIPI DSI 4/3 lane、Video Mode 和标准 DCS 命令，也列出 1280×800 模式的典型时序。

v1.0.24 工程按 4-lane RGB888、DSI Video Pulse 配置：

| 参数 | 配置值 |
| --- | ---: |
| 有效分辨率 | 1280×800 |
| 像素时钟 | 72.4 MHz |
| H sync / back porch / active / front porch | 20 / 68 / 1280 / 72 DCLK |
| V sync / back porch / active / front porch | 2 / 21 / 800 / 15 行 |
| MIPI 数据通道 | 4 lane，RGB888 |
| 屏幕初始化 | DCS SWRESET、SLPOUT、DISPON |
| 触摸 | 暂时关闭 |

按 1440 DCLK × 838 行和 72.4 MHz 计算，帧率约 60.0 Hz。SDK 已有 DSI controller/PHY 驱动；工程通过启动期读取 ENV 选择 LVDS 或 MIPI，并在 framebuffer probe 前把 PD18–PD27 切换到相应引脚复用。

当前资料没有给出该模组实际的 IFSEL/LNSW/PNSW strap 电阻配置、FPC lane 对应、lane 极性，也没有模组厂提供的已验证 DSI lane mapping。代码使用 SDK 的默认 lane mapping/polarity 和 4-lane 设定；必须在目标板确认这与模组 strap、FPC 走线一致。编译成功不等于已验证出屏。

## 触摸

CS001 依用户要求仅启用显示，UART 状态返回 TOUCH=DISABLED，不会启动现有 GT911 驱动。CS000 继续使用 GT911。恢复 CS001 触摸还需要 ATMXT1066TD 的 RT-Thread 初始化配置、I²C 地址、IRQ/RESET 接线和坐标方向信息。

## 串口无应答排查

v1.0.22 的 UART0 RX 存在无应答问题。v1.0.23 修正为按 UART 回调提供的长度读取，并增加启动 READY 行；v1.0.24 沿用该接收实现。若没有 READY，先确认新 OS 已启动以及 UART0 TX 连线；若有 READY 但发送命令无应答，确认 USB-UART TX 接到板端 PA1 RX、串口参数为 115200/8N1、TX/RX 交叉且共地。上电时避免拉低 PA0/UBOOT。

## 目标板验收

1. 用 3.3 V USB-UART 连接 UART0，设置为 115200/8N1。
2. 上电后收到当前 profile 的 READY 行。
3. 发送 CS000，确认 1024×600 LVDS 和 GT911；若当前为 CS001，应保存后重启切回。
4. 发送 CS001，确认保存后重启，串口返回 READY，屏幕按 1280×800 MIPI-DSI 出图；触摸当前保持关闭。
5. 发送其他 5 字节代号，收到 UNSUPPORTED_CODE。

本次仅执行 SDK 主机编译和镜像检查，没有连接、烧录或擦除开发板。CS001 MIPI 出图、lane/极性、色彩、冷启动和 UART 实收发仍需目标板验收。
