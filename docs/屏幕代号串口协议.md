# 屏幕代号串口协议

## 接口

- UART：UART0，115200 baud，8 data bits，no parity，1 stop bit（8N1）。
- 命令：5 个 ASCII 字符，例如 `CS000`；可直接发送，也可追加 CR、LF 或 CRLF。
- 应答：ASCII 文本，以 CRLF 结束；RT 控制台仍静默，没有额外调试日志、校验和或二进制帧头。
- 命令接收由 RT-Thread 工作线程处理，不占用 LVGL 线程。
- 每次启动 UART0 命令服务时，主动发送当前配置行，便于确认固件/链路已就绪。

板端 UART0 为 3.3 V TTL。连接 USB-UART 时交叉连接 TX/RX 并接共地，不要连接 RS-232 电平。D133CBS 板卡 UART0 TX 使用 PA0，PA0 同时连接 UBOOT 按键启动采样；避免在上电时把该线拉低。

## 命令与应答

| 命令 | 应答 | 含义 |
| --- | --- | --- |
| `CS000` | 当前已是 CS000 时：`CS000,OK,ACTIVE=CS000,RES=1024x600,TOUCH=GT911`；从 CS001 切回：`CS000,OK,REBOOTING,RES=1024x600,TOUCH=GT911` | 将选择写入官方 ENV；需要重启时自动重启。 |
| `CS001` | 当前已是 CS001 时：`CS001,OK,ACTIVE=CS001,RES=1280x800,TOUCH=DISABLED`；从 CS000 切换：`CS001,OK,REBOOTING,RES=1280x800,TOUCH=DISABLED` | 保存 CS001 到官方 ENV 并重启；当前只启用显示，不启用触摸。 |
| 其他代号 | `<代号>,ERR,UNSUPPORTED_CODE,ACTIVE=<当前代号>` | 当前固件未登记该代号。 |

启动时发送：`CS000,READY,RES=1024x600,TOUCH=GT911`，或切换后 `CS001,READY,RES=1280x800,TOUCH=DISABLED`。

示例：

```text
电脑发送：CS000\r\n
开发板：  CS000,OK,ACTIVE=CS000,RES=1024x600,TOUCH=GT911\r\n

电脑发送：CS001
开发板：  CS001,OK,REBOOTING,RES=1280x800,TOUCH=DISABLED\r\n
设备重启后：CS001,READY,RES=1280x800,TOUCH=DISABLED\r\n
```

`CS000` 为 1024×600 LVDS/GT911。CS001 选择 1280×800 LVDS，并在重启时由 panel probe 读取官方 ENV；实际切换需要重启，不会热插拔 LVDS 时钟。CS001 暂不启动触摸输入；切回 CS000 会恢复 GT911。UART0 命令应答和启动状态行是正式 HMI 配置唯一的 RT 输出。

## CS001 显示配置与资料边界

新资料的封面把产品规格号列为 `EK79202DA`、客户料号 `ICEK7920321XXXXXXX01`；正文是 EK79202D 2052 通道 source driver/TCON 芯片的 preliminary datasheet。它补充了 1280×800 LVDS 输入的候选时序，但不是完整的 LCD 模组接线规格。

芯片 datasheet 的 1280×800、60 Hz HV mode 表给出：像素时钟典型值 72.4 MHz（范围 66.3–78.9 MHz）、每行 1440 DCLK（显示区 1280）、含同步脉冲的 HBP 88 DCLK、HFP 72 DCLK、HSYNC 脉宽 2–40 DCLK；每帧 838 行（显示区 800）、含同步脉冲的 VBP 23 行、VFP 15 行、VSYNC 脉宽 2–20 行。工程使用 20 DCLK/2 行作为同步宽度，剩余 porch 分别为 68/21；按典型值计算约为 60 Hz。脉宽具体配置和模组实测值仍需上板确认。

同一芯片资料说明支持 LVDS 6/8-bit，并以 `IFSEL[1:0]`、`LNSW[1:0]`、`PNSW`、`RES[2:0]`、`LVFMT`、`LVBIT` 等 pin strap 选择接口、lane/polarity mapping、分辨率与数据格式；它列出 1280×800 的 RES 编码，但没有给出该客户模组实际 strap 电阻/连接器到 D133 LVDS lane 对应表。D133 SDK 原版 `panel_simple.c` 只有 1024×600、1920×1080 和 custom descriptor，`aicfb_probe()` 在设备初始化时只选一次 panel，LVGL 随后按 framebuffer 创建单一 display。

触摸方面，先前的 LCJ0010R1EA0Y16CP100 样件确认资料提到 ATMXT1066TD、I²C/3.3 V 和 1280×800 触摸分辨率；新 EK79202D PDF 没有 ATMXT1066TD 寄存器/对象表或 CTP 接线资料。按用户要求，v1.0.23 的 CS001 仅初始化显示，跳过 LVGL 触摸输入；SDK 的 `bsp/peripheral/touch/Kconfig` 没有 ATMXT1066TD 项，也没有对应驱动源码。

v1.0.23 已加入 CS001 的 1280×800 LVDS 候选 timing，并使用 D133 当前单链路 LVDS/8-bit VESA 和低有效同步设置。仍需在目标板确认实际模组 strap/lane/polarity 与像素颜色。如果图像异常，串口发 `CS000` 可写回原 profile 并重启。进一步确认显示硬件还需要：

1. `ICEK7920321XXXXXXX01` 模组接口/排线图，特别是 LVDS 单/双链路、D0–D3/clock lane 对应、极性、VESA/JEIDA、HV/DE 模式，以及上电、复位和背光时序/引脚。
2. EK79202DA 模组实际的 `IFSEL/LNSW/PNSW/RES/LVFMT/LVBIT` strap 设置或供应商已验证的接口配置。

恢复触摸时还需要 ATMXT1066TD 的 RT-Thread 驱动/初始化配置，或控制器完整协议、I²C 地址、板端 I²C/IRQ/RESET 接线、报告格式和坐标方向。

启动选择由项目 overlay 在 `aicfb_probe()` 前从 `hmi_screen` ENV 读取，串口切换通过官方 `fw_env_write/fw_env_flush` 保存并重启。为此 FAL init 使用 RT-Thread init level 2.9，确保面板 probe 前可读取 ENV；没有直接改写 Flash 地址。CS001 的触摸保持禁用，避免把 GT911 驱动当作 ATMXT1066 驱动。

## 串口无应答排查

用户已手动烧录 v1.0.22，但该版本存在 UART0 接收无应答问题。v1.0.23 改为按串口回调提供的字节数读取，并在服务启动时打印 `READY` 行。若启动行和命令应答仍都没有，检查板端 UART0 RX=PA1 是否接到 USB-UART TX、TX/RX 是否交叉且共地；若只看到 BootROM/SPL 输出，确认新 OS 是否启动到系统页面。上电时不要拉低 PA0/UBOOT。

## 验收步骤

1. 使用 3.3 V USB-UART 连接 UART0，设为 115200/8N1。
2. 上电后应先收到当前 profile 的 `READY` 行。
3. 发送 `CS000`，期望返回当前 1024×600/GT911；如果当前为 CS001，应返回 `REBOOTING`，重启后回到 CS000。
4. 发送 `CS001`，期望返回 `REBOOTING`，重启后显示 1280×800；触摸当前关闭。
5. 发送其他 5 字节代号，期望返回 `UNSUPPORTED_CODE`。

以上是协议预期结果。v1.0.23 只完成 SDK 构建，实际串口收发、1280×800 画面、切换回退和 strap 兼容性仍需在目标板验证；CS001 触摸按当前范围暂不启用。
