# TCP 直写 OTA 候选版 v1.0.113

本机定制版为 v1.0.112，公开版 v1.0.113 不包含私有工具箱 Key 和默认 WiFi 密码。新协议必须与配套工具箱补丁一起使用，首次由用户手动烧录工厂 IMG；安装补丁后重新打开工具箱。旧工具箱的 SD 暂存开始命令被新固件拒绝，新客户端也拒绝不支持直写的旧固件，不静默降级。

## 流程与槽位

工具箱发送包长、摘要、产品/硬件、版本与 RSA 签名。开发板验证签名并等待屏幕确认，之后将接收数据交给官方 `ota_shard_download_fun`，不落 SD 暂存。A 运行写 B，B 运行写 A，OS 与资源槽配对。当前槽位未健康确认或 OS/资源槽不一致时拒绝开始。

流式边界校验只允许 ota_info.bin、d13x_os.itb、rodata.fatfs，校验元数据 CRC、成员加和、长度、重复成员和结束标记；签名包摘要在接收结束时再次匹配。官方引擎的 OS/资源完成标志和全部校验通过后，才调用 `aic_upgrade_end` 提交官方冗余 ENV。断线失败不激活目标槽。普通 OTA 不含 SPL、DATA，未直接操作 Flash 地址。

接收确认表示官方引擎已接受对应数据；引擎可能仍有自己的内存缓冲，不等同每个 TCP 确认都有 Flash 读回保证。分区擦写、写保护和引导状态提交使用官方实现。

## 阶段耗时

开发板显示目标槽、进度、KiB/s，以及签名、屏幕确认、接收写入、完整性核对、ENV 提交、总耗时。接收与写入重叠，合并统计。流式 CRC/SHA 累计计入接收写入，末尾摘要核对计入校验阶段，可能不足 1 ms。

工具箱日志另外记录连接与信息读取、签名/确认、接收写入、最终提交、重启健康确认耗时。健康确认仍以版本、槽位和设备已确认状态为准。

## 配套协议

LNET 帧结构、CRC 和 DATA/COMMIT 编号不变，新增 `0xD106` 开始命令，负载为原 132 字节元数据加签名字节。INFO/HEALTH 增加 `stream_ota:2` 能力。首个 DATA 至少覆盖 636 字节元数据，当前客户端使用 16 KiB 块。原 `0xD101` 暂存开始命令返回不支持。

实际工具箱安装版从根目录加载 Python3.8 .pyc，单改 Source 中的 .py 不会生效。补丁检查已核对模块的 SHA256，手动备份并替换 D133 客户端，不修改其它开发板客户端。用户必须先退出工具箱再运行补丁。

## 验证与限制

已完成 SDK OS 编译、生成包的白名单/破坏数据/SPL 映射拒绝测试、RSA 验签；实际编译的 Python3.8 客户端通过本机模拟设备的正常提交、旧能力拒绝、错误偏移不提交测试。

经用户允许曾执行两次旧协议 SD 暂存接收诊断，不发送签名/COMMIT/重启，16 KiB 和 4 KiB 块均复现超时，另一条状态连接持续正常。该结果不能证明新直写流程的 Flash 可靠性。

未进行真实 Flash 写入、掉电恢复、A/B 切换回滚、硬件阶段显示与速度验收；未自动烧录。C 流式校验器已交叉编译，尚无本机原生 C 运行测试环境。候选版不得当作已完成硬件验收的生产固件。
