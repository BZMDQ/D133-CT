# v1.0.48 BMP 扇区对齐读取

单缓冲和双缓冲都使用同一个对齐读取函数：文件位置向下对齐到 4096 字节，读取尾部向上对齐并截断到实际文件大小；转换阶段使用缓冲内的 prefix 偏移直接访问像素，不搬动整批数据。4 KiB 边界兼容 SDK 配置允许的 512/1024/2048/4096 字节扇区。

输入缓存使用 RT-Thread 的 rt_malloc_align/rt_free_align 配对管理；每块在有效批次容量外预留 8 KiB 覆盖窗口两端，对齐分配还有分配器自身开销。内存不足时仍缩小批次或退回单缓冲。

文件头读取前关闭 stdio 缓冲；像素阶段使用 DFS/POSIX 的 fileno、lseek、read。输入像素起点可以不对齐，例如用户提供的 1024×600、24 位 BMP 起点为 54；读取窗口对齐后以偏移 54 访问像素。颜色转换、图片方向、居中及裁剪保持原逻辑。

主机脚本 `python scripts/verify_bmp_sector.py <原始BMP路径>` 验证原图全屏和裁剪窗口的像素字节一致性，以及扇区边缘、文件尾和缓冲容量。它是读取布局模型检查，并未运行目标 C 程序或测量 SD 速度。

## 手动验证

备份配置和数据后使用 AiBurn 手动选择 v1.0.48 IMG；工厂包包含配套 Bootloader，可能覆盖 ENV 和 DATA。未执行自动烧录或擦除。

使用同一张 32 GB FAT32 SD 卡和原始 1024x600.bmp 对比 v1.0.47/v1.0.48 打开时间，并检查颜色、方向、裁剪、取消及连续重开。另需验证 16/32 位 BMP 和其他分辨率、屏幕测试图片、SD 插拔与 OTA。实际对齐是否减少 DMA 临时缓冲及提速幅度均需上板确认，不能由编译或模型测试推定。
