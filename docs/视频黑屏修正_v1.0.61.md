# v1.0.61 黑屏、卡顿与 720P60 MJPEG

v1.0.60 的单帧显示器在 LVGL 每次完成绘制后将视频对象设为隐藏。SD 读入下一帧有间隔时，LVGL 会重绘该区域，露出黑色背景。v1.0.61 在帧已画入显示缓冲后保留视频对象和最后一帧，并暂停文件页与状态栏的后台刷新，直到下一帧就绪。它针对已发现的黑屏窗口修正了显示生命周期；仍需同一开发板和同一视频实测确认。

## 输入与测试

SDK 和芯片仅支持 MJPEG 视频硬解，MP4 是可用封装，H.264/H.265 仍不支持；AVI、MP4、MOV 均须使用 MJPEG 基线视频、无音频、偶数宽度，最大 1280×720。用户提供的原片是 1280×720@60 MJPEG AVI，码率约 35.9 Mbps（约 4.5 MB/s）。AVI 中有 3591 个视频帧，最大压缩帧约 146 KiB，小于 SDK 的 512 KiB 比特流缓存；持续 SD 吞吐仍是主要压力。

先在 SD 卡播放随包 5 秒低码率测试片（约 10.2 Mbps）。再尝试原片；转换脚本将画面改为 720P60/MJPEG。原片转换实测仍约 13.7 Mbps，FFmpeg 报告 rate-control underflow，说明复杂画面的 MJPEG 编码不能严格达到目标值，可能降低画质。可从这里查看本机生成的原片低码率版本：[本机转换视频](</D:/Users/ws2608007/Desktop/D113/资料整理/构建临时/video_720p_test/抖音样片_720P60_MJPEG_目标码率10M.mp4>)。

视频覆盖播放时，状态栏和文件管理任务结果暂停刷新，避免后台内容触发视频区域重绘。帧显示时在 LVGL 绘制完成后归还单帧解码缓冲。画面停留可帮助区分读卡停顿和解码停止；实际播放性能仍须板上测量。

## 构建与升级

SDK OS 编译成功，OS 3008512 字节，RODATA 3178496 字节，均在 A/B 槽位范围内。签名 OTA 通过 CPIO 完整性、SPL 映射拒绝和 RSA/SHA256 检查，已安装的工具箱客户端可识别 v1.0.61 包。板端视频输出、SD 实际吞吐和 OTA 尚未在本次修改后验证。OTA 只适用于新版分区布局且当前版本低于 1.0.61 的设备；工厂烧录前请备份 DATA。
