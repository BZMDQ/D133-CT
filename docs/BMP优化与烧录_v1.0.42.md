# v1.0.42 BMP 打开优化与烧录

## 改动

BMP 的可见区域读取支持带行填充和适度水平裁剪的连续批读，每批最多 32 行、缓存上限 128 KiB。非末批连同行尾间隙读取，使下一批继续顺序读；末批精确限制在像素区内。极宽图片仍按可视窗口逐行读取，内存不足时降低批次，最终回退单行。

保留通用 16/24/32 位 BMP 解码、较小图片居中不拉伸、较大图片居中裁剪。文件管理与屏幕测试共用 image_preview，因此两处同时生效。解码继续运行在 RT-Thread 图片线程，NOR 读速不作调整。

## 验证

`python scripts/verify_bmp_batch.py` 检查 72 组读取边界、行填充、中央裁剪、正倒序和单行回退。该脚本是主机读取布局模型验证，不代表在目标设备上运行了完整 C 解码器。

主机模型中，1201×67 的 BGR24 图片在 1024×64 窗口读取时，由逐行 64 次读取降为 2 次批读、1 次初始定位。减少调用次数不等于打开耗时同比下降；实际 SD 卡耗时、显示颜色和连续打开稳定性需上板验证。

## 手动烧录

工厂镜像：`downloads/d13x_d133cbv-hmi-nor_v1.0.42.img`。这是含配套 Bootloader 的首次部署/工厂 IMG，并非日常 OTA 包。工厂烧录可能覆盖 ENV、资源及数据，请先保留需要的配置和文件。

1. 在 AiBurn 选择该 IMG，核对型号 d13x、板级 d133cbv-hmi-nor、版本 1.0.42 和介质 spi-nor。
2. 按开发板的 USB BROM 操作连接设备，由操作者手动开始烧录。
3. 重启后，在文件管理器打开 SD 卡的 16/24/32 位 BMP；再进入屏幕测试，确认同分辨率测试图可用。
4. 对比同一 SD 卡、同一图片的打开耗时，检查红绿蓝颜色、上下方向、居中/裁剪和返回后再次打开。

本次不执行真实硬件烧录、擦除或复位。视频播放未包含在此版本，CS001 背光电气兼容性不属于本次 BMP 优化的验证结果。
